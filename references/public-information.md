# 公开信息补充

报告能够识别企业全称且用户未禁止联网时必须尝试查询。主体匹配尚未可靠时可以检索，但不得把结果归入客户名下。优先顺序：国家企业信用信息公示系统及政府网站、裁判/执行与监管公开渠道、企业官网、权威行业协会与统计部门、可信商业媒体。

每条记录：查询主体、统一社会信用代码（如可得）、查询日期、信息发生日期、来源名称、网址、摘要、主体匹配置信度。

至少使用企业全称；报告提供统一社会信用代码时必须优先使用。可用法定代表人、注册地址/经营地址、成立日期辅助排除重名。搜索引擎未收录、官网验证码或无法自动查询时，如实记录查询限制。

重点辅助：登记状态与股东/法定代表人变化、经营范围与报告描述、行政处罚/经营异常、被执行与司法风险、行业景气与政策变化。

## 业务判断优先，不把检索过程当结论

后台审计层保留查询词、原始数字、来源、网址和时间；客户经理阅读版只呈现有业务意义的判断。不得用“查询了多少网站”“行业增加值增长多少”代替分析。

后台可以形成五项判断，但客户经理阅读版只展示其中已有可靠结论的项目：

| 判断项 | 允许结论 | 判断要求 |
|---|---|---|
| 工商主体 | 可靠匹配 / 部分匹配 | 企业名称、信用代码、法定代表人、地址等能否指向同一主体；通常只用于后台控制信息归属 |
| 登记一致性 | 一致 / 存在差异 | 经营范围、法定代表人、地址、存续状态与报告是否一致 |
| 公开风险 | 未发现已公开重大异常 / 发现需关注事项 | 仅在主体可靠匹配后判断异常经营、处罚、执行、重大司法风险 |
| 行业判断 | 景气偏好 / 中性 / 偏弱 / 分化明显 | 综合需求、竞争、价格、回款和政策，给出方向性结论 |
| 对本客户影响 | 有利 / 中性 / 不利，并说明原因 | 必须落到订单、议价、成本、回款或经营稳定性；不能由宏观信息直接证明客户自身表现 |

阅读版展示规则：

- 无法可靠匹配、无法判断、查询未命中和查询受限全部留在后台，不进入正文；
- 查询日期、来源网址、行业参考资料和宏观数字全部留在后台，不进入正文；
- 如果只有行业判断可靠，就只展示“行业判断”和“对本客户影响”；
- 如果没有任何可靠且有业务意义的判断，省略整个公开信息小节。

表达示例：

- `工商主体：可靠匹配。登记信息与报告核心描述一致，未发现需立即升级的已公开异常。`
- `行业判断：中性、企业间分化明显。需求仍在，但小微服务企业议价能力和回款质量取决于客户结构；对本客户不构成行业性否定，也不能补足其自身现金流证据。`
- 对无法形成结论的工商主体，不在客户经理阅读版展示；仅在后台记录匹配状态和限制。

约束：

- 搜索未命中只在后台记录，不得在阅读版写“不存在”“无异常”或“无法判断”。
- 重名、简称或主体不唯一时标记 `UNCERTAIN`，不得拼接到客户名下。
- 当前信息不能直接证明历史调查时点状态；必须说明时间差。
- 公开信息冲突属于核对线索，不直接替代客户经理线下尽调。
