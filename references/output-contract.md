# 客户业务初审与报告质量双层输出

## 默认：业务初审版

输出首先回答“客户和本次授信业务到底怎么样”，其次才回答“报告写得怎么样”。两者不得混为一谈。

### 1. 材料边界

只用一句话说明：本次仅基于调查报告，报告中引用的流水、税务、征信、权证和估值信息按客户经理记载理解，AI未重复核验。

### 2. AI综合初审结论

放在输出最前面，是全文唯一一份完整业务判断。至少回答：

- 客户经营资质整体偏好、中等偏好、一般、偏弱或暂无法判断，依据是什么；
- 本次融资用途、金额、期限、还款安排是否与经营相匹配；
- 第一还款来源是否具有基础、充分性如何；
- 第二还款来源或保证担保能够形成多大程度的风险缓释；
- 已识别的主要客户和业务风险是什么；
- 综合属于可初步支持、有条件支持、需审慎判断或暂无法形成意见，并说明该意见不是最终审批决定。

同时标注判断置信度为高、中或低。置信度取决于报告内核心事实是否充分，不等同于客户风险等级。

### 3. 判断依据

分为三组，避免概念混淆：

1. **主要正面因素**：报告已有事实支持的经营、财务、资产或担保优势。
2. **已识别风险因素**：报告已有事实显示的客户或业务风险，例如收入下降、高负债、历史逾期、客户集中、关联占款或押品顺位风险。
3. **判断受限事项**：报告信息不足，导致无法充分判断的事项。只能表述为“不确定/需进一步判断”，不能写成客户负面事实。

### 4. 核心复算

展示已完成且有意义的资金需求、同比、资产负债、抵押率等计算，并说明口径。计算结果属于业务判断依据。

### 5. 公开工商与行业信息

公开信息部分以结论为主，默认用简洁表格或短段落直接回答已有可靠结论的项目：

| 判断项 | 客户经理阅读版输出 |
|---|---|
| 工商主体 | 可靠匹配 / 部分匹配；一般作为后台归属控制，不必单列 |
| 登记一致性 | 一致 / 存在差异 |
| 公开风险 | 未发现已公开重大异常 / 发现需关注事项 |
| 行业判断 | 景气偏好 / 中性 / 偏弱 / 分化明显 |
| 对本客户影响 | 一句直接业务判断，落到订单、议价、成本、回款或经营稳定性 |

对无法可靠匹配、无法判断或查询受限的项目，客户经理阅读版直接省略；如果没有任何有效公开判断，则省略整个小节。查询日期、主要来源、链接、详细查询词、网页摘要、宏观数据和匹配过程全部留在后台审计层。行业数字只能作为后台判断依据，不能替代“行业如何、对客户有什么影响”的结论。

### 6. 报告质量与客户经理分析评价

放在客户业务判断之后，单独评价：

- 报告内容是否完整；
- 客户经理对主营趋势、行业、经营模式、资产累积、关联企业、融资理由、两项还款来源、风险措施的分析是否充分；
- 哪些结论强于报告证据；
- 哪些内容建议补写或调整表述。

使用简洁表格：`分析内容｜评价｜问题｜建议`。相近问题合并，不要重新生成一份客户风险结论。

## 分类约束

生成前必须对每项发现分类：

- `CUSTOMER_POSITIVE`：客户或业务正面事实；
- `CUSTOMER_RISK`：报告已经显示的客户或业务负面事实；
- `ASSESSMENT_UNCERTAINTY`：信息不足造成的判断限制；
- `REPORT_GAP`：报告内容缺失；
- `ANALYSIS_WEAKNESS`：客户经理分析逻辑或表述不足；
- `VERIFICATION_ITEM`：客户经理应在线下确认的事项。

只有`CUSTOMER_RISK`可以直接进入“已识别风险因素”。`REPORT_GAP`和`ANALYSIS_WEAKNESS`不得伪装成客户风险；它们只能影响报告质量或判断置信度。

## 默认隐藏

不展示内部分类代码、规则编号、证据编号、全部PASS项目、NOT_APPLICABLE项目、因报告外材料未输入产生的NOTRUN项目、状态统计、文件指纹和脚本日志。

## 按需：审计追溯版

用户明确要求审计版时，输出完整规则结果和证据链，并额外记录每项发现属于客户风险、判断不确定性、报告缺项还是分析不足。业务初审版与审计版必须来自同一批事实。
